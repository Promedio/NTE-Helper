在 AutoHotkey v2 中，物理按键已经抬起但宏逻辑却**无法自动停止（无限连点）**，这是一个非常经典且棘手的问题。

通过分析你的代码架构，问题并不在于你的定时器逻辑写错了，而是由于你采用了 **`SetTimer` 循环配合 `GetKeyState(..., "P")` 轮询** 的传统设计。这种设计在面对高频 `Send` 操作或复杂系统环境时，极易触发以下几个底层冲突：

---

### 核心原因分析

#### 1. 键盘钩子失步（漏掉抬起事件）—— 最主要原因

你的宏在高速循环发送 `Send("{" this.trigger_key " Down}")` 和 `Up`。当脚本以极高频率向系统注入虚拟按键时，如果此时系统遭遇瞬间卡顿（如游戏掉帧、CPU 满载），或者**你松开物理按键的瞬间刚好与 `Send` 发送指令撞车**，AutoHotkey 的键盘钩子（Keyboard Hook）就会**漏掉**操作系统传来的物理物理抬起（`WM_KEYUP`）信号。

* 信号一旦漏掉，AHK 内部的按键状态缓冲就会锁死在“按下”状态。
* 导致 `GetKeyState(..., "P")` 永远返回 `true`，`monitor_key_call` 永远无法进入终止逻辑。

#### 2. `HotIfWinActive` 导致的焦点切换冲突

你在创建热键时绑定了 `HotIfWinActive(active_title)`。

* 当你按住热键时，宏启动。
* 如果在按住期间，游戏窗口突然失去焦点（如弹出了系统通知、不小心 Alt+Tab、或者游戏自身弹窗），该热键的激活条件立即失效。
* 虽然后台的 `SetTimer` 还在异步运行，但由于窗口焦点切换，操作系统可能不再向原窗口的钩子发送该按键的物理抬起消息，导致 `GetKeyState` 状态死锁。

#### 3. 修饰键（Shift/Ctrl/Alt）的物理干扰

如果在连点期间，用户无意中按下了其他修饰键，系统发送的组合键消息会干扰 AHK 钩子对单一按键物理状态的判定，同样会导致 `GetKeyState` 阶段性失效。

---

### 彻底解决方案：引入 `Up` 抬起热键

在 AHK v2 中，要彻底解决“无法停止连点”的顽疾，最佳实践是**放弃用定时器轮询 `GetKeyState(..., "P")**`，而是利用 AHK 自身的事件驱动机制 —— **明确注册一个 `按键 Up` 热键**。

只要操作系统触发了抬起事件，AHK 的 `Up` 热键响应级别远比 `GetKeyState` 轮询更精准、更安全。

#### 改造建议

你可以为 `RepeatKeystrokeSingle` 和 `RepeatKeystrokeMultiple` 类拓展一个显式的 `Stop()` 方法，并在 `create()` 时为热键绑定对应的 `Up` 事件。

##### 1. 架构改造示例（以 Single 为例）

在 `RepeatKeystrokeSingle` 类中添加或修改：

```autohotkey
; 显式停止宏的方法
Stop() {
    ; 关闭所有相关定时器
    SetTimer(this.press_key, 0)
    SetTimer(this.monitor_key, 0)
    
    ; 确保发送最后的抬起指令，防止游戏内按键粘连
    Send("{" this.trigger_key " Up}")
    
    ; 重置控制标记
    this.key_block := false
}

; 此时你的 monitor_key_call 可以作为双保险，或者直接移除
monitor_key_call() {
    if GetKeyState(this.remap_key, "P") == false {
        this.Stop()
    }
}

```

##### 2. 在 `create()` 注册时绑定 `Up` 热键

修改你的静态 `create` 函数，在注册原热键的同时，顺便注册一个对应的 `Up` 热键：

```autohotkey
static create(Self := hks) {
    for active_title in ACTIVE_TITLE_LIST {
        HotIfWinActive(active_title)

        if cfg.data.交互重复.映射按键.data != "" and cfg.data.交互重复.触发按键.data != "" {
            macro_rks := Self.macro.RepeatKeystrokeSingle(cfg.data.交互重复.触发按键.data, cfg.data.交互重复.映射按键.data)
            hotkey_rks_enable_state := cfg.data.交互重复.启用状态.data == true ? "On" : "Off"
            
            ; 1. 绑定按下事件
            Hotkey(cfg.data.交互重复.映射按键.data, macro_rks, hotkey_rks_enable_state)
            
            ; 2. 绑定抬起事件（核心修复：利用 ObjBindMethod 绑定刚刚拓展的 Stop 方法）
            macro_rks_stop := ObjBindMethod(macro_rks, "Stop")
            Hotkey(cfg.data.交互重复.映射按键.data " Up", macro_rks_stop, hotkey_rks_enable_state)
        }
        
        ; Multiple 逻辑同理，遍历 key_list 时同步注册 key_name " Up"
        ; ...
    }
    HotIfWinActive()
}

```

##### 3. 增加轻量级“安全阀”（可选）

如果你不想大改架构，可以在 `press_key_call()` 的顶部加上**窗口激活状态校验**。如果连点进行时窗口已经不是当前游戏窗口，强行中断，防止卡死在外：

```autohotkey
press_key_call(is_first_keystroke := false) {
    SetTimer(this.press_key, 0)
    
    ; 安全阀：如果当前窗口已经不再是目标游戏窗口，直接停掉连点
    if !WinActive(A_WinDelay) { ; 或者指定具体的活性检测
        this.key_block := false
        return
    }
    ...
}
```
